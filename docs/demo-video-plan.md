# デモ動画の計画（3分）v4

v3 からの変更：コアの考え方を「双方の意思決定と認知負荷を、システムに外出しする」に据え直した。作品名は sou-buddy。打合せの記録・ご家族へのお願い（窓口の TODO）・関係先と地図・バディを画に入れた。
演者は立てない（画面の録画＋作者のナレーション）。家族・発言はすべて架空。金額は実データの集計値（品目ごとの中央値を丸めたもの）。実在の社名・人名・ロゴは出さない。

## 一本の筋

**「決めることと、覚えておくことは、sou-buddy に。双方が、悔いのないお別れに気持ちを向けられるように」**

葬儀では、担当者とご遺族の双方が、高額で取り返しのつかない複雑な意思決定を迫られる。その負担と認知負荷をシステムに外出しする。
同じ架空の家族（山田家：お風呂と庭の花が好きだった母、84歳。孫は東京から3日後に着く。費用は抑えたい。菩提寺は市外）の打合せを、記録とご家族の窓口まで追う。

## 撮り方

- **画面の録画はローカルで**：`cd web && npm run build && npx next start -p 3100`（開発用の「N」バッジが映らない）。1440×900。
- 撮る前に「最初から」を押して山田家を空にする（打合せの記録・お願い・デモのバディも空に戻る）。ガイドが出たら「閉じる」。
- 「打合せを終える」のあとに台本の再生を続けると、第2回の会話として続く。記録の場面を撮り終えたら「最初から」を押す。
- モデルの出力は毎回変わるので3回撮り、寄り添いの言葉と提案・記録がきれいに出た回を使う。1回の再生で AI を40〜60回呼ぶ（1日の上限は既定で3000回）。
- 窓口は Chrome の端末表示（Pixel 7）で撮る。
- `web/demo/*.record.ts`（Playwright）で自動で録ることもできる。

## 作るもの（HTML で作って録画）

1. 冒頭のカード2枚（ご遺族の決めごと・担当者の決めごと）と「決めることと、覚えておくことは、システムに」
2. 仕組みの図（左から右へ光る）
3. 数字カード（意地悪な場面の合格数）と作品名のカード

どれも1枚に一文。色と書体は担当者の画面にそろえる。音は静かなピアノ1曲＋作者のナレーション。
