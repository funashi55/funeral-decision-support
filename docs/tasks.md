## 0. 技術構成（このタスク分解の前提）

| 層 | 採用 | 選んだ理由 | つまずいたときの代替 |
|---|---|---|---|
| 画面とサーバー | Next.js（App Router）＋ TypeScript、Vercel に配置 | 画面と API を1つにまとめられ、配置の手間が最小 | ― |
| データ | Supabase（Postgres ＋ Realtime ＋ 行単位の認可） | 担当者が確定すると遺族のスマホへ即時に反映できる。家族ごとの認可を DB で強制できる | ローカルの SQLite ＋ 定期取得 |
| 文字起こし | Soniox のリアルタイム API を**ブラウザから直接**接続（短命の一時キーをサーバーで発行） | 常駐サーバーや WebSocket の中継が不要になる | ブラウザ標準の音声認識 → それも不可ならメモ入力モード |
| 抽出 | Claude Haiku 5.5（構造化出力） | 速く安い。打合せのテンポに合う | ― |
| 推奨・判定・検品 | Claude Opus 5.5（effort は推奨 medium・判定 low を起点に調整） | 判断の質が作品の芯 | ― |
| 遺族の窓口 | Claude Managed Agents（道具は3つだけ） | 確定の権限を構造として持たせない | Messages API ＋ Tool Runner（同じ3つの道具） |
| 画像編集 | Gemini の画像モデル | 部分編集ができる | 事前に生成した画像を「事前生成例」と明記して表示 |
| 似た家族の集計 | 家業の基幹システムから作った**匿名集計表**（JSON、30件未満のセルは除外）をリポジトリに同梱 | 数字をモデルに作らせない。個人情報を一切含めない | ― |

## 1. 全体の流れと依存関係

```
[A 土台] ─┬─> [B 決定モデル] ─┬─> [D 意思決定支援エンジン] ─┬─> [G 担当者の画面] ─┐
          │                   │                              │                     ├─> [J 撮影・提出]
          ├─> [C 実データ集計] ┘                              ├─> [H 遺族の窓口] ───┤
          │                                                  │                     │
          └─> [E 文字起こし・抽出] ───────────────────────────┘                     │
[F 知見化・評価] ──（D に知見 Skill を供給）                                           │
[I 祭壇イメージ（限定版）] ─────────────────────────────────────────────────────────┘
[K Claude Code の使い方の証拠づくり]（全期間で並行）
```

**クリティカルパス**：A → B → D → G → J。ここが遅れると提出に響く。E・H・I は D と並行で進め、遅れたら削る。
