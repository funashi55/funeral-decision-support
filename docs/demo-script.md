# デモ動画の台本（3分）

筋は**新人とベテランの対比**です（spec §7）。家族・発言はすべて架空。画面の操作は `web/demo/record.spec.ts` で何度でも同じように撮れます（`npm run demo:record`）。

| 時間 | 画面 | ナレーション（案） |
| --- | --- | --- |
| 0:00–0:25 | 黒地に数字。「受付から葬儀まで 中央値 4日」「打合せで決める項目 41」（基幹システムの匿名集計）。当時のメモ「担当を二つ持つと頭がいっぱいで、提案とかできない」 | 葬儀社の受付から葬儀まで、中央値で4日。そのあいだに、ご遺族は41の項目を決めます。私はフューネラルプランナーとして2年間、この打合せの席にいました |
| 0:25–0:50 | 紙の打合せシートとプラン表（ロールプレイ）。新人がプランの説明に追われ、喪主が予算と親戚の話で考え込む | 本当は、どう送りたいかに時間を使ってほしい。でも実際は、日程とプランと費用の話で、ご家族は疲れてしまいます |
| 0:50–1:30 | 担当者の画面。「▶ 打合せを再生」。会話が流れ、段階の表示が「信頼関係」から進む。見落とし注意（市外のお寺・遠方の親族・お悔やみ欄）が出る。最後に「お別れの仕方」：家族が望むお別れ（お風呂好きの母を清めて送り、孫に顔を見せたい）、選択肢ごとのできること・できないこと・費用・取り消せるか、似た家族の選び方（参考）、根拠を開くと喪主の言葉とベテランの知見 | 会話から、ご家族が望むお別れを言葉にします。費用のかからない選択肢を必ず含め、金額や割合は価格表と実データから差し込みます。数字をAIには作らせません |
| 1:30–1:45 | 「守る線の検査を通過」「最初の案は差し戻し」の表示。docs/redteam の 20/20 の表 | 不安をあおる言い回しや、多数派に合わせさせる言い方は、判定役が止めます。誘導されやすい20の場面で、すべて線を守りました |
| 1:45–2:00 | プランの案のタブ。3つの幅が費用を抑える順に並び、「含まれないもの」が先に出る。生花の色を「紫」で確定すると祭壇のイメージが変わる | 案は価格の上下ではなく、気持ちの幅として並べます。祭壇はイメージを見ながら決められます。画像は Claude が検品し、頼んでいない装飾が描かれたものは出しません |
| 2:00–2:20 | Claude Code で veteran-knowledge の Skill を動かす様子。テーマ別のサブエージェントが並行で走り、「元の発言に戻れない規則：0件」 | 推奨の根拠は、ベテランへの聞き取りです。Claude Code のサブエージェントが「こういう時はこうする」を元の発言つきで取り出し、すべての規則が本人の言葉に戻れることを確かめてから使います |
| 2:20–2:45 | 夜、スマホの窓口。「火葬は何時からでしたか」に案内役が記録から答える。「湯灌はしたほうがいい？」は担当者に回す。翌朝、担当者の画面に届き、返事をするとスマホに出る | ご家族は夜でも、決まったことを確かめられます。窓口は勧めたり決めたりはしません。担当者に回し、確定は担当者がします |
| 2:45–3:00 | 家業の葬儀社のロゴは出さず、打合せの席の写真（架空） | 家業の葬儀社で、経験の浅い担当者の打合せから使い始めます。使うほど、ベテランの判断が会社に残っていきます |

## 撮影の前に

- `web/.env.local` に API キー。推奨と判定は実際の Opus が動くため、結果は毎回少し変わる
- 推奨の場面は2〜3回撮り、守る線の差し戻しが出た回を使うと判定役が見せられる
- 窓口はスマホ実機か、Chrome の端末エミュレーション（Pixel 7）で撮る
