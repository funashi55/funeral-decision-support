# 開発の記録：最初のアイデアから今の形まで

この作品は、最初のアイデアから3回、大きく形を変えています。変えた理由と、変えたときに捨てたものを残します。仕様の全文は [spec.md](spec.md)、作業の一覧は [tasks.md](tasks.md) です。

## 1. 応募時：グリーフケアのエージェント

応募のときに考えていたのは、遺族の悲しみに寄り添って話を聞くエージェントでした。

ヒアリング（2026-11-03、Q1〜Q27）で出発点を掘り下げると、作者が現場で一番引っかかっていたのは「悲しみ」そのものより、**悲しみの中で難しい決定を短期間にいくつも迫られ、別れの時間が削られていること**でした。また、AI が遺族の心に直接働きかける作品は、大会の作成禁止リストにある「AI メンタルヘルスアドバイザー」に近づいてしまいます。

そこでグリーフケアは主役から外し、遺族と話す場面での**観点**として残しました（Q28）。今の窓口の案内役が、つらい声を受け止めて診断や助言をせず担当者や相談窓口へつなぐのは、このときの判断です。

## 2. ヒアリング後：打合せ中の推奨

次の形は「打合せの会話を拾い、ベテランならどうするかを担当者に示す」道具でした。ベテランと新人の差は「遺族の様子を読む」「段取りの組み立て」「要望と予算の調整」にあり（Q7）、ベテランの技は「こういう時はこうするといいですよ」という推奨にある（Q11）、という作者の実感が土台です。

この時点で、もっとも重い線を決めました。**高いプランへ誘導しない**（Q16）。悲しみの中の家族は言われるがままに選びがちで、推奨の道具はそのまま営業の道具になり得るからです。

## 3. アドバイザーの講評：祭壇イメージを絞り、推奨を主役に戻す

外部のアドバイザー2人（実装の現実性の観点と、審査基準での採点の観点）に講評を受けました。採点は各10点満点でインパクト6・デモ5・Claude の活用6・深さと実行力5。

指摘を受けて、守る線を「安い案を添える」から**並べ方・言い回し・追加費用・家族の希望との整合まで検査する**形に強め、テストで証明することにしました。祭壇イメージは上位プランとの見比べをやめ、標準祭壇の花の色だけの限定版にしました。上位プランの絵を並べること自体が誘導に見えるためです（Q33）。

## 4. 現場調査：確認表から、意思決定支援へ

作者の家業の葬儀社の基幹システムの集計と、作者が働いていた当時のメモを調べました（11/4。詳細は非公開）。

受付から葬儀まで中央値4日、打合せで決める項目は41。当初は「決めたことの確認表」を作れば楽になると考えていましたが、数字とメモを並べると、確認表だけでは抜本的には変わらないと分かりました。難しいのは記録ではなく、**家族ごとに正解が違う決定そのもの**だったからです（Q38）。

そこで芯を「100件100様の難しい意思決定の支援」に据え直し、確認表・発注リスト・CSV は記録と共有の土台に下げました。デモの中心にする決定は、遺族がもっとも迷い、後悔しやすく、不安をあおる営業がもっとも起きやすい**お別れの仕方**にしました（Q40）。

## 5. 実装中に見つかったこと

- **言い回しの検査は、単語では足りなかった。** 最初の検査は止めるべき19件のうち6件しか止められず、「病状が悪化して入院」「泣き崩れ」のような穏やかな文まで止めていた。お体・お顔と変化の語の組み合わせで見るように書き直した（19/19・8/8）
- **問題はモデルではなく、こちらの文にあった。** 判定役が、サーバーが固定で持つ湯灌の説明文「長い闘病のあとに」を、家族が言っていない闘病を持ち出す文だと指摘した
- **罪悪感は、有料の選択肢の理由にされやすい。** 「何もしてあげられなかった」と話す家族の場面で、モデルが2回とも罪悪感を湯灌の理由にして止められた。指示に「罪悪感や後悔を有料の選択肢の理由にしない」を加え、推奨を出せないときは選択肢の事実だけを並べるようにした
- **画像モデルは、頼んでいないところまで描き変える。** 生花の色だけを変える指示で、ピンクの1枚だけ祭壇の台が明るい木目に変わっていた。Opus の検品が見つけて不合格にし、作り直した
- **案内役は、自分が担当者に回したことを忘れる。** 守る線に落ちた返事を決まった文に差し替えると、回したことが履歴から消え、次の問いかけで同じ依頼をもう一度回した。履歴に「回し済み」を残すようにした

## Claude Code の使い方

- **計画と記録**：仕様（spec.md）とタスク（tasks.md）を先に書き、守る線を CLAUDE.md に置いて毎回読ませた
- **Skill**：ベテランの知見化の手順を `.claude/skills/veteran-knowledge` に置いた。テーマ別のサブエージェントが並行で取り出し、すべての規則が元の発言に戻れるかを機械で確かめてから知見に書き出す
- **フック**：守る線に関わるファイルを編集するたびに、言い回しの検査と推奨の検査を流す（`scripts/hooks/guard-tests.sh`）
- **テスト**：単体テストと Playwright の E2E を、機能を足すたびに流した。モデルを呼ぶ検証（意地悪な場面・知見の前後比較・画像の検品）は手で流し、結果を `docs/` に残した
- **画面の確認**：Chrome DevTools MCP で、PC とスマホの幅の実際の見た目を確かめた
