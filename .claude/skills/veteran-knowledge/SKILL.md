# ベテランの知見化

聞き取りの文字起こしから、推奨エンジンが使う知見（`web/src/knowledge/rules.json`）を作る。
**すべての規則は、文字起こしの中の元の発言に戻れなければならない。** 戻れない規則は書き出さない。

## 前提

- 文字起こしは `docs/private/interview/transcript.txt` に置く（公開しない。`.gitignore` 済み）
- 聞き取りの前の知見は `web/src/knowledge/rules.author-memo.json` に残っている（前後の比較に使う）
- 元の発言は `rules.json` に載り、公開リポジトリに入る。**ベテラン本人の確認と、発言を載せる許可を得てから** `--write` する。社名・取引先・個人名が発言に含まれていたら、その部分を除いた発言を引く

## 手順

1. 文字起こしを読み、話題の切れ目をつかむ（全文を一度に渡さず、テーマごとに関係する箇所を抜き出す）
2. **テーマごとにサブエージェントを並行で起こす**（Agent ツールを1つのメッセージで5つ同時に呼ぶ）。テーマは
   `flow`（進め方）・`farewell`（お別れの仕方）・`schedule`（日程）・`plan`（プランと費用）・`logistics`（見落としと手配）。
   各サブエージェントには、次の「サブエージェントへの指示」と、そのテーマに関係する文字起こしの箇所と、
   決定項目の一覧（`web/src/domain/decisions.ts` の id と label）を渡す
3. 各サブエージェントは `docs/private/interview/fragments/<theme>.json` に断片を書く
4. 取りまとめと検査：
   ```bash
   cd web && npm run knowledge -- ../docs/private/interview/transcript.txt ../docs/private/interview/fragments
   ```
   元の発言に戻れない規則があれば、その断片を直す（発言を言い換えていることが多い。文字起こしからそのまま引き直す）
5. 規則の一覧をベテラン本人に見てもらう（F8）。本人の考えと合わない規則は断片から外す
6. 本人の確認が済んだら `--write` で `rules.json` を置き換え、`npm test` を通す
7. 前後の比較：`npm run compare:knowledge`（聞き取りの前の知見と後の知見で推奨を出し、ベテランの答えとの一致を比べる。モデルを呼ぶので費用がかかる）

## サブエージェントへの指示

> あなたは葬祭ディレクターの聞き取りから、新人が打合せで使える知見を取り出します。テーマは「{テーマ}」です。
>
> - 1つの規則は「どんな時に（when）」「どうする（do）」「なぜ（why）」「元の発言（quote）」「関わる決定項目（decisionIds）」
> - quote は文字起こしから**一字一句そのまま**抜き出す。要約や言い換えをしない。句読点の違いは構わない
> - ベテランが言っていないことを足さない。一般論や自分の知識で補わない
> - 高いプランや有料の選択肢へ誘導する話、不安をあおる話は、規則にしない（守る線。`CLAUDE.md` を参照）
> - 個人名・社名・取引先が quote に入るときは、その箇所を除いた範囲を引く
> - 出力は次の形の JSON だけ：
>   ```json
>   { "theme": "farewell", "rules": [ { "when": "", "do": "", "why": "", "quote": "", "decisionIds": ["laying_in_style"] } ] }
>   ```

## 完了の条件

- 規則が5〜10件以上あり、`npm run knowledge` で「元の発言に戻れない規則：0 件」
- ベテラン本人が確認済み
- `npm test` が通る（知見の形式と、決定項目の存在を検査している）
